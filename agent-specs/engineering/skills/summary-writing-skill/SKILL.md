# 总结写作技能

## Trigger and Scope
- 当需要编写年终总结、季度总结、月度总结、周报或日报时使用。
- 适用对象：工程/产品/管理/跨团队协作的对内总结与同步。
- 不用于：对外公关、法律/合规材料或绩效打分表。

## Workflow
1. 确认总结类型与时间范围（年/季/月/周/日 + 起止日期）。
2. 收集输入：目标、结果、指标、影响对象、风险/阻塞、下一阶段责任。
3. 将技术工作翻译为业务结果与战略抓手（技术动作 → 业务指标 → 战略意义）。
4. 按“价值证明”组织内容：结果闭环、杠杆/复用、资产沉淀、变化与升级、关键矛盾。
5. 选用对应模板并填充（见 assets/）。
6. 运行自检（见 references/quality-checklist.md），标记缺口并提出补充问题。
7. 输出成稿 + “缺口/待补数据”与“需要确认的问题”。

## Required Inputs
- 总结类型（年终/季度/月度/周报/日报）
- 时间范围（起止日期）
- 角色/团队
- 关键成果（3-5 条，含指标或证据）
- 影响对象（用户/业务/系统/团队）
- 风险/阻塞（若有）
- 下一阶段计划（责任 + 范围 + 预期影响）
- 读者/接受方（可选）

## Defaults
- 语言：中文
- 风格：克制、数据导向、战略对齐、避免流水账
- 结构：优先使用 assets 模板；无模板时使用“概览/成果/价值&杠杆/资产/风险/计划”

## Output Format
- 使用对应模板输出正文。
- 结尾追加：
  - 缺口/待补数据
  - 需要确认的问题

## Guardrails
- 不写任务清单，写结果闭环与影响。
- 不夸大，不编造数据；缺失数据必须标记 TODO。
- 技术细节只作为支撑，必须翻译成业务指标或战略意义。
- 避免情绪化与口号式表达。

## Verification & Acceptance
- 每个“成果”都有指标/证据或明确 TODO。
- 至少包含 1 条“杠杆/复用/机制”或“资产沉淀”。
- 至少包含 1 条“变化/升级”（如从 A 到 B）。
- 明确下一阶段责任与边界。

## Iteration Loop
- 首稿 → 反馈（缺口/不清晰之处）→ 修订 → 最终稿。
- 记录最高影响的缺口并给出下一轮改进建议。
