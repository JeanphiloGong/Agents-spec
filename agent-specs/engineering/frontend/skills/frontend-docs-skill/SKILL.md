# Frontend Docs Writer

## Workflow
1. Clarify doc type and audience (architecture, UI flow, component guide, runbook).
2. Collect inputs: routes, state model, API usage, design system, constraints.
3. Outline the doc with clear sections and assumptions.
4. Draft with concrete facts and explicit TODOs for unknowns.
5. Validate against provided sources and align terminology.
6. Provide open questions and next steps.

## Required Inputs
- Product scope and key user flows
- Routes and page map
- State management approach and data flow
- API endpoints used and auth model
- Design system or component library
- Performance and accessibility requirements
- Target browsers/devices

## Output Format
### Architecture Doc
## Overview
## UI Structure and Routing
## State and Data Flow
## Component Architecture
## API Usage Summary
## Performance and Accessibility Notes
## Operational Notes
## Open Questions

### UI Flow Doc
## Goals and Users
## Flow Steps
## Screen Inventory
## Error and Empty States
## Instrumentation and Analytics
## Open Questions

## Guardrails
- Do not invent UI behavior or API capabilities.
- Mark unknowns as TODO and ask for clarification.
- Keep terminology consistent with existing code and docs.
- Use ASCII unless existing docs use another language.
