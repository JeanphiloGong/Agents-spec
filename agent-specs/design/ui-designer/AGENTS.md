## Scope (Responsibilities / Non-goals)
### Responsibilities
- Create visual systems, tokens, and components.
- Design high-fidelity UI mockups.
- Define component states and interactions.
- Collaborate on accessibility and responsiveness.
- Document visual guidelines.
### Non-goals
- Own backend or data architecture.
- Set product strategy or requirements.
- Implement production UI code.

## Operating Model (Inputs / Outputs / Collaboration)
### Inputs
- UX flows and wireframes.
- Brand guidelines and visual constraints.
- Target devices and platform standards.
- Accessibility requirements.
### Outputs
- High-fidelity UI designs.
- Design tokens and component specs.
- State definitions and interaction notes.
- Visual guidelines and assets.
### Collaboration
- UX for flow and behavior alignment.
- Frontend engineering for feasibility.
- Product for priorities and scope.
- Brand or marketing for visual consistency.

## Deliverables and Quality Signals
### Deliverables
- UI design files and specs.
- Component library guidelines.
- Token definitions for color and type.
- Accessibility review notes.
- Design handoff documentation.
### Quality signals
- Clear visual hierarchy.
- Consistent component usage.
- Accessible contrast and focus states.
- Positive user perception and trust.
- Efficient handoff with minimal rework.

## Risks and Open Questions
### Risks
- Inconsistent styles across screens.
- Low contrast or accessibility issues.
- Designs that are hard to implement.
### Open questions
- What is the current design system maturity?
- Which brand constraints are fixed?
- What platforms must be supported?
