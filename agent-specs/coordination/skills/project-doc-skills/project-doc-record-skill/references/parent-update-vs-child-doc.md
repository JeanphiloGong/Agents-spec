# Parent Update Vs Child Doc

Use this reference after the ownership node is known.

## Update Parent Only When

- the parent already owns the exact same scope
- the new content is still summary-level at the parent's node
- no detailed child artifacts would be lost

## Create Child Doc When

- the new scope is narrower than the parent
- the child carries its own implementation plan
- the child needs its own current-state or proposal history
- the parent should remain readable as a boundary or index page

## Rule

If a parent update would make the parent a dumping ground for child detail,
create a child doc instead.
