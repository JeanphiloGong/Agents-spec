# README Body Priority Rules

Use this reference when deciding how much a README should explain the layer
itself versus the docs system around it.

## Repository Root `README.md`

Prefer:
- project identity and purpose
- core capabilities
- quick repository orientation
- a short pointer to `docs/README.md`

Avoid:
- long reading orders
- full formal-doc inventories
- module-by-module documentation routing

## Node `README.md`

Prefer:
- node purpose
- responsibilities or boundaries
- main flow
- key areas or child nodes
- short related-doc pointers near the end

Avoid:
- leading with docs-tree explanation
- replacing runtime explanation with only file lists
- mirroring the full local docs landing page

## `docs/README.md`

Prefer:
- reading order
- document categories
- current authority routes
- formal-doc discovery

Use this page when the job is to explain the documentation system itself.

## Rule

README explains the thing. `docs/README.md` explains the documentation about
the thing.
