# Reader Entry Model

Use this reference when deciding how readers should enter and traverse a
repository's documentation.

## Default Entry Sequence

Prefer a top-down path:

1. `Start Here`
2. `System Overview`
3. `Current State`
4. `Active Changes`
5. `Key Decisions`
6. `Stable Contracts`
7. `Development`
8. `Operations`
9. `Governance`

## Rules

- The root page should be a reading map, not a raw folder list.
- `System Overview` explains boundary, modules, and major flows.
- `Current State` explains how the system works now.
- Lower layers should remain reachable from the entry path without taxonomy
  knowledge.
