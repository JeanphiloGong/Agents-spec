# Canvas 笔记与思维导图

仅在用户要求图形整理时使用。生成 Obsidian 内置 Canvas 能打开的 `.canvas`
JSON 文件，不依赖思维导图插件。默认不改已有白板；编辑已有图时保留不相关的
节点、连线和布局，按主技能的已有内容修改规则执行。

## 操作步骤

1. 从用户内容或指定笔记提取中心主题和少量分支。层级表示归类，不把猜测画成
   已证实的因果；需要补充建议时在节点中标注“AI 建议”。
2. 先保存本次需要引用的 Markdown 笔记，再生成 Canvas 的相对路径。
   原始材料很少时可以直接使用文字节点，不必为每个分支新建一篇笔记。
3. 中心主题放左侧，子主题向右展开。给每层固定间距；根据节点内容估算高度，
   为同层分支及其子树预留空间，避免覆盖。用短摘要显示全貌，详情链接笔记。
4. 构造 JSON 对象后使用 JSON 序列化器写文件，不手工拼接字符串。
5. 回读并验证下列结构和引用；能在已授权的 Obsidian 操作环境中打开时，再检查
   文字截断、重叠与阅读顺序。不能视觉验证时如实标明，不临时安装控制工具。

## 最小文件结构

```json
{
  "nodes": [
    {
      "id": "topic",
      "type": "text",
      "text": "# 学习规划\n目前的想法，尚未确定安排。",
      "x": 0,
      "y": 0,
      "width": 300,
      "height": 180
    },
    {
      "id": "note",
      "type": "file",
      "file": "02-主题笔记/学习笔记/英语学习.md",
      "x": 420,
      "y": 0,
      "width": 360,
      "height": 240
    }
  ],
  "edges": [
    {
      "id": "topic-note",
      "fromNode": "topic",
      "fromSide": "right",
      "toNode": "note",
      "toSide": "left",
      "toEnd": "arrow"
    }
  ]
}
```

示例的笔记路径只在该文件存在时有效；不要直接照抄到用户仓库。

## 文件检查

- 顶层含 `nodes` 和 `edges` 数组；节点与连线各有唯一的字符串 `id`。
- 节点包含 `type`、数字 `x`/`y`、大于零的数字 `width`/`height`。
- 本技能新建节点使用 `text` 或 `file` 类型，分别提供字符串 `text` 或 `file`。
- `file` 使用从仓库根目录开始的相对路径，包含实际扩展名，目标存在且不越出仓库。
- 连线的 `fromNode` 和 `toNode` 均引用真实节点；使用的方向值为
  `top`、`right`、`bottom` 或 `left`，箭头值为 `none` 或 `arrow`。
- 从坐标和宽高检查节点矩形没有非预期重叠；视觉检查仍需在应用内完成。
- 内容与源笔记一致，没有把层级归类误写成因果、进度或承诺。
